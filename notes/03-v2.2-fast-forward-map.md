# V2.2 — fast, type-stable forward map (build log)

Location on disk: `invernaderos/invernaderosV2.2/GreenhouseSim/` (beside `invernaderos2.0`).
Built from 2.0's proven physics; reuses 2.0's `Project.toml` + `Manifest.toml`
(so package versions are identical to the working 2.0 env; uses `OrdinaryDiffEq`,
not `DifferentialEquations`).

## RESULT — benchmark (measured 2026-09, macOS arm64)

Type stability: `@code_warntype rhs!` shows every local `::Float64`, `Body::Nothing`,
**no `::Any`/`::Union`**. Fully inferred.

| Measurement | V2.2 | old 2.0 (README) |
|---|---|---|
| single `rhs!` call | 338 ns, **0 alloc** | — |
| `climate_rhs` kernel | 22 ns, **0 alloc** | ~1 µs region |
| full 2-day `forward_map` (4 params) | **5.6 ms, 59 KiB** | full model ~19–28 s, **13.33 GiB** |

Allocations dropped from **GiB → KiB**. This is the type-stability payoff and the
property that makes large MCMC / RL workloads practical. Globals were the problem.

Sanity: `length(T2)==51` (matches obs); `T2[1:3]=[296.15,296.15,284.948]`;
`CO2` relaxes to outside value 834.7; `RH` briefly ~102% (model permits
supersaturation; 2.0 does the same — confirm in regression).

## What it does differently (the speed fix)

- **No globals.** All 151 constants (115 climate + 36 crop) load from the JSON
  configs into ONE concrete `NamedTuple` of `Float64`, passed to the ODE via `p`
  and read with literal destructuring `(; alpha1, …) = p`. This replaces 2.0/V2.1's
  `eval(:(global …))` importer — the cause of the ~13 GiB allocations.
- **Concrete weather/controls** structs of callable interpolants (no `Dict{Symbol,Any}`).
- **Inference flexibility kept, without globals:** `update_params(base, names, x)`
  overrides any named subset once per MCMC proposal (function barrier), then `solve`
  runs a fully specialized RHS. Same freedom as 2.0's globals, no speed penalty.
- Physics is a faithful port (`climate_rhs`, `assimilation`), so outputs match 2.0.
  Micro-opt: `minimum([...])` → `min(...)` in photosynthesis (removes an alloc/call).

## Gotchas hit during bring-up (all resolved)

- Path: config/data live 3 levels up from `test/` (INV = `../../..`), not 2.
- DataInterpolations API: this env resolved a NEW version — use
  `extrapolation=ExtrapolationType.Constant`, not `extrapolate=true`. `_const_interp`
  in weather.jl tries new API then falls back to old, so it works across versions.
- Must export `SimBase` and `simulate` from the module (not just SimContext).
- device_commit_files silently no-op'd one write once; verify on-disk with grep and
  fall back to an in-place edit on the device if a commit doesn't take.

## Known fidelity note / open item

- `assimilation` is called with `LAI = I9` (radiation), reproducing a 2.0 quirk so
  the regression matches exactly. The real LAI should be used once the growth model
  exists — switch the `assimilation(...)` call in `forward_map.jl`/`rhs!`.
- Multi-day control indexing fixed vs 2.0 (controls now offset per day via
  `controls_t0`), so runs longer than 1 day are correct.
